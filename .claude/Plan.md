## 1. DIR-006：Vultr 自建 Linux 中继（待执行，Luna 接手）

**当前只启动阶段 1**。阶段 2—4 为排定的后续里程碑，前一阶段验收与代码审核通过后再顺序推进。本轮仅完成收口与计划，无远程业务代码或部署成果。

### 固定范围与实现约束

- 保留 LAN 无服务器模式、旧 UDP/TCP 端口、LANC 魔数和帧，默认不开启远程；新增用户自有 Linux 服务器中继，客户端主动连接。选择 Vultr 约 5 美元共享 CPU 档作为小规模预算目标，无需 GPU；1 vCPU/1 GB/25 GB/1 TB 的公开规格来自 Grok 页面核对记录，账户实际套餐/IPv4/地区/附加项/税费/流量仍待确认。
- 优先 TLS TCP，C# 用系统 SslStream，Python 用标准库 ssl；服务端优先 Python 3 asyncio/ssl/json，不前置 Docker、Nginx、Redis、大型数据库或新客户端运行库。TCP 443 不等于 HTTPS，能否通过公司网络必须先实测；若只能经 HTTP 代理，回到传输选择讨论，不能并行做多套通道或以关闭证书验证解决。
- TLS 至少 1.2，验证链/名称/有效期，优先现有域名/子域名和公认 CA，设计续期和更新。无域名时先核实 IP 证书/固定证书方案；不得静默忽略验证。服务器能看到明文，不能宣称端到端加密。
- 沿用 NetworkService 门面、Models、Presenter、设置与本地历史；C# 核心跨平台共享，显式更新 Linux 链接。新对象先评估职责/生命周期，不机械新增 partial 或复制聊天业务。Python 客户端坚持标准库；UI 按需读 Windows 上下文和 GrokBot 规范。
- 原生 csc 路径不能证明实际 Framework 或 TLS 版本。帧候选为大端 UInt32 长度（含类型/负载、不含自身）＋1 字节类型＋负载，控制/文字候选 UTF-8 JSON；**阶段 1 验证编解码后才在阶段 2 冻结 v1**。不假定 System.Text.Json 在原生四引用内，不能用配置/历史中的正则抽取解析公网帧；额外系统程序集先列明兼容影响并审核。
- 远程路由与 LAN 广播隔离：不自动上传 LAN 内容/主机名/IP/联系人；不自动将旧私聊失败转公网；远程不进入 peer.IP 直连或 GetLocalEndpointForTarget，公网出口按系统路由。
- 首版只做预登记少量设备的在线私聊和受限在线文件。暂不做公开注册/搜索、群聊、多设备账号同步、离线队列或文件存储、断点续传、打洞、音视频、端到端加密、持久化重试与严格恰好一次；单节点不承诺高可用。

3. 编写最小隔离服务/客户端验证 TLS、候选帧、中文/Unicode、拆包粘包、EOF/超长/无效帧与标准编解码兼容，不读取真实历史或启动 LAN 扫描。探针和代码仍遵守中文注释、单文件上限与零冗余依赖；在实施报告记录文件入口及命令，不产生第二份设计基线。

6. 通过条件：三路径编解码与 TLS 均有真实结果，证书校验不可绕过，真实网络可达，最低运行时和依赖已确定。缺少任一必要条件时标记未验证与下一步，继续可独立完成部分；不将阶段 1 标完成，不冻结协议、不进入阶段 2。阶段报告与代码走 CRDocs 审核，结论通过后刷新当前态并提交推送。

### 阶段 2：在线文字（排队，阶段 1 通过后）

- 冻结远程 v1 的类型、长度上限、JSON/其他已验证编解码及错误规则；校验长度后才分配缓冲，区分认证前/后，设置认证和半包读取超时。
- 管理员本机登记设备/空间并分配每设备至少 32 字节安全随机令牌；服务端存校验摘要，不提供公开注册/无保护管理接口。令牌在 TLS 内认证，不写 URL/日志/仓库；本地凭据保护与便携复制行为在接入前定稿。撤销/轮换立即断旧连接、拒绝旧凭据。
- 持久远程 DeviceId 与现有随机 LAN LocalId 分开；服务端根据认证连接填发送者和授权范围。稳定服务器＋空间＋设备构成无歧义远程会话键；验证其落盘文件名不碰撞，不能仅依赖分隔符替换；不自动合并 LAN 与远程历史。
- 同设备新认证连接先验凭据再替换旧连接，不等失联超时、不当作认证失败。旧回调按代次核对，不清掉新连接；本机换网/睡眠正常恢复。另一份凭据副本被顶替后停止自动互抢，导入入口提示复制目录不产生新设备。
- 消息 ID＋认证发送者＋服务器/空间组成有界进程内去重键；同键重复重 ACK、不重显，不同发送者同 ID 都显示。状态区分发送中/对端应用已接收/失败/结果未知；中继写出不算对端 ACK，ACK 不代表已读或历史可靠写盘。断线未确认标未知，不自动重放；首版用户重新发为新消息，跨重启不保证去重。
- 独立接收循环、串行发送、有界队列；指数退避带扰动，认证失败/版本不兼容停止重试。候选心跳 30 秒、失联 90 秒、重连上限 60 秒；候选每空间 10 设备、服务 50 认证连接、正文 16 KiB、每设备 5 条/秒突发 10，均待测。未认证/握手/IP/失败认证另设资源上限。
- 验收：四组合 Windows↔Windows、Windows↔Linux C#、Windows↔Python、Linux C#↔Python 双向文字；按真实产品构建路径测试。覆盖身份重启、睡眠/换网、替换与旧回调、凭据副本、去重、ACK 丢失、离线、服务端重启、非法身份/跨空间/撤销/错版本；LAN 群发不选中远程，远程文字不落 LAN 直连，文件未实现时明确拒绝；会话/历史/退出回归与代码审核通过。

### 阶段 3：在线文件（排队，阶段 2 通过后）

- 候选单文件 100 MiB、单设备 1 个传输、块 64 KiB；另行定服务级在途数、全部应用层/流写缓冲总预算和速率，数值通过压测定稿，不缩减 LAN 文件能力。
- 接收者明确接受，按认证身份绑定双方/传输 ID/长度/顺序，安全文件名、临时文件、累计长度与摘要核验，完成再命名。服务器只转发不存整文件，不按客户端路径读写本机；远程事件按认证设备/会话键归档，不用昵称猜测或回落 BROADCAST。
- 背压传递至发送者，公平块调度保证文字交互；超时/断线/取消释放状态。单连接队头阻塞若实测不满足目标，再评估第二文件连接，不提前实现。
- 验收：各组合双向摘要一致；上限/超限、慢接收、多对并发总预算、取消/断线/临时文件清理、路径穿越、同昵称不同身份、文字响应；远程文件不连 peer.IP、不调用物理网卡绑定；通过 CRDocs 审核。

### 阶段 4：部署与运行验证（排队，阶段 3 通过后）

- 非 root systemd 托管、最小低端口权限与防火墙、配置校验、证书续期/重载、受限无敏感日志、元数据备份恢复、回退；VPS 不开放 LAN 旧端口。证书工具属部署依赖，不能因此把新运行库塞进客户端。
- 监测控制台出站与应用用量，文件月预算/告警及超额前拒新文件、保留文字容量；单收件人 S 文件约入 S/出 S，未来 N 人扇出约出 N×S。应用限额不覆盖攻击/系统流量，不承诺账单绝不超套餐，不自动升级实例。
- 在实际配置记录 20 连接的空闲/文字/文件 CPU/RSS/流量/延迟；初步目标服务 RSS≤200 MiB、60 秒空闲平均 CPU＜单核 5%，不达标先限队列/连接，不声称是硬件保证。连续运行至少 24 小时无持续资源增长；LAN 发现/文字/大文件/退出、原生与 Linux 产物完整回归。无实机的项目保留未验证，不宣布完成。
