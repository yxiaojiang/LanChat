# Plan.md — 当前活跃计划

> 最近刷新 2026-11-18。开发分支 `main`。[公开基线 v2.0.16](https://github.com/yxiaojiang/LanChat/releases/tag/v2.0.16) 对应 `a0e49c1`。

## 首要任务 · 完成 Linux 桌面重构（LC-LINUX-001）

状态为方案已采纳，实施待开始。执行顺序为 **1 → 2 → 3b**，**3a 实机原型验证可与 1、2 同期推进，3b 等 2 和 3a 通过**。从步骤 1.1 开始。按 [采纳记录](../PlanDocs/LC-LINUX-001/STATUS.md) 和 [第 2 轮审核](../PlanDocs/LC-LINUX-001/REVIEW-R2.md) 执行。

已确认三项落地规则。Linux 沿用 GrokBot 视觉指标，图标及圆角资源可由构建期 GDI+ 生成后随 Tk 客户端交付。系统文件／文件夹选择器沿用桌面样式，应用内菜单、提示和接收者选择采用暗色叠加层。Python 源码按职责拆分并遵守 1000 行预警、1500 行上限，由标准库 `zipapp` 生成单文件 `.pyz`。详见 [项目规则](Rules.md)。

### 步骤 1 · 修复收发主流程与构建链

- [ ] **1.1 固定复现样例。** 在隔离配置和临时端口下复现群聊首次重绘与异常后的历史编辑、离线私聊丢草稿、非默认监听端口被改写、文件同名归错、TCP 短读与文件无最终确认。记录旧版行为及期望结果。
- [ ] **1.2 修复 Python 主界面状态。** 系统消息先分类，重绘结束和异常时恢复历史只读。会话按钮接通导航，自动接收按配置初始化。私聊先验证在线状态，离线保留输入。用操作标识将等待、成功或失败投递到原会话。手动 IP 直连显示校验、等待和结果。辅助文字使用 9.5 pt、`#8E8E93`。
- [ ] **1.3 修复节点学习和发现。** Python 与共享 C# 文字学习路径均保留已确认的监听端口和主机名。未知节点临时用 `38889`，后续由公告更新。Python 用标准库取得本机物理 IPv4 与掩码，跳过虚拟网卡，优先采用可信同子网源地址。仅在源为回环或可确认跨网段时使用合法的非回环公告地址。掩码未知时保留源地址及未确认状态。校验公告端口并覆盖无默认路由和 TUN。核心入口为 `src/linux/lanchat.py`、`src/NetworkService.Transfer.cs`、`src/NetworkService.Discovery.cs`。
- [ ] **1.4 修复文件结果和短读。** 定长字段读满并识别 EOF，保留 LANC 帧和 ACK 语义。文件按发送者 ID 和连接端点归档，通过最后的落盘 ACK 才显示成功。覆盖拒收、超时、断开、缺确认、重复文件名及并发任务各自的终态，保留 64 KiB 流式传输。群聊发文件支持无人提示、单人直发和多人暗色选人。
- [ ] **1.5 修通 ELF 与 Debian 候选包。** 按脚本位置修正 `packaging/build-all.bat`、`src/linux/LanChat.Linux/build-linux.bat` 和 `packaging/build-deb.py` 的项目与产物路径。从干净目录生成 x86_64、ARM64 ELF。让 `Tools/Publish.bat` 传递重建、打包失败状态，只有成功才打印成功。校验 amd64 包内 ELF 与本轮 x64 输出的 SHA-256 一致，另验 all 包的 Python 入口。构建失败时退出，交付记录写明缺失的运行时或产物。
- [ ] **1.6 验收与代码审核。** 用 `Tools/Compile.bat` 验证 Windows 原生构建。运行短读、收发及两方向非默认端口回归。至少在一台安装候选 `.deb` 的 x86_64 Ubuntu 22.04 或 24.04 与一台 Windows 实机完成发现、私聊、群聊、文件 SHA-256、拒收和中断验证。候选 Windows 验证修复后的双向行为，再与公开 `v2.0.15`、`v2.0.16` 各验兼容，记录旧版已知限制。并验桌面入口、缺 `python3-tk` 提示、无头及显式 `--cli`、新旧 x64 ELF 互通，在 ARM64 验 all 包与新 ELF。记录机器、网段、发现用时、防火墙、默认路由和 TUN 状态，提交 [独立代码审核](../CRDocs/STATUS.md)。

### 步骤 2 · Python 真解耦、单文件交付与历史

- [ ] **2.1 按生命周期拆源码。** 在步骤 1 的回归基线上拆分启动／CLI、网络服务、会话状态和 Tk 界面。保留网络线程到 Tk 主线程的队列契约，避免 GUI 导入影响无头 CLI。给新增或实质修改的类与公共方法补中文文档字符串，核对行数及职责边界。
- [ ] **2.2 接入标准库 `zipapp`。** 由源码和资源构建单文件 `.pyz`，迁移打包、版本同步、桌面启动和命令行入口。以归档所在目录区分便携与安装形态。验收旧安装升级、便携运行、已有配置及接收路径、显式 `--cli`、缺 Tk 与 SSH 无头路径。
- [ ] **2.3 接入会话历史。** 使用与 Windows 一致的 `LAN-<IPv4>`、独立群聊键、`history_BROADCAST.jsonl` 和 `history_peer_<键>.jsonl`。字段名、可选 `RemoteAddress`、本地时间毫秒格式与 Windows 对齐。写入用 UTF-8 原文并遵循现有 Windows 解析器支持的转义集合，处理其他控制字符时遵循 Windows 写入契约。双向样例覆盖中文、引号、反斜杠、换行及旧缺字段行。
- [ ] **2.4 恢复和归并会话。** 当前节点 ID、地址和端口用于路由，经确认的 IPv4 用于历史归档。核对同名不同 IP、同 IP 节点 ID 更新、直连后再被发现、不同设备复用 IP 的已知边界。展示离线档案昵称。文件可多选并分别反馈结果，历史卡片对本机可用的文件提供打开／定位。
- [ ] **2.5 验收数据与升级。** 安装及便携模式分别验重启、重载、尾部坏行、不可写路径、未完成传输状态和清理确认。用 Windows 与 Python 互读样例，回归新版桌面包和两种 CLI 入口。

### 步骤 3a · Linux 实机验证 Tk 绘制方案

- [ ] **3a.1 对比控件与资源。** 在 Xorg 和 GNOME Wayland 中记录实际 Tk 后端和 XWayland 情况、Tk 版本、`tk scaling`、桌面缩放。比较 Canvas 与构建期 GDI+ 生成资源的圆钮、胶囊、滑块和气泡角，采集普通及分数缩放截图，核对半透明边缘、非默认强调色、资源体积和旧 Tk 回退。
- [ ] **3a.2 对比消息流与输入。** Canvas 和带资源的 Text 两个原型各使用 2000 条文字、文件及系统消息，记录切换、滚动、缩放重绘耗时和位置保持，验证选择复制。用 fcitx5 与 ibus 分别核对候选窗、预编辑、Enter 提交和发送，以及 Ctrl+Enter 换行。实测暗色叠加层的焦点、Escape、点外关闭和文件选择器。
- [ ] **3a.3 记录选型。** 保存对比截图和一页实测记录，明确采用的绘制方式、输入法绑定和兼容回退，然后进入正式 UI。

### 步骤 3b · 完成 GrokBot 双栏与设置

- [ ] **3b.1 实现双栏与消息控件。** 左栏集中搜索、连接、会话状态、未读及个人入口。右侧提供标题、圆角气泡、可操作文件卡片和 64 px 输入胶囊，附件钮 36 px，发送钮 44 px，主输入 11 pt。会话和聊天滚动统一 4／5 px 浮动暗色滑块，验证拖动、滚轮和无溢出隐藏。
- [ ] **3b.2 接入图标、弹层和设置。** 复用 GDI+ 的合规图标几何，构建期生成图标及圆角资源并随 `.pyz` 交付。窗口内菜单、提示和选人使用暗色叠加层，系统文件选择器保留样式例外。分类设置接通自定义接收目录、自动接收、历史管理、主题、强调色及独立字体，核对即时应用和重启恢复。
- [ ] **3b.3 执行最终回归。** 用真实 Linux 桌面截图对照 Windows 和设计规范，覆盖窄窗、普通及分数缩放、长历史、滚动、中文输入与键盘。复跑阶段 1、2 的互通、安装、升级和 CLI 核心路径。按架构和组合登记结果，缺环境的组合标为未验证。候选包与公开发布分别记录，公开发布使用项目指定入口并等用户指令。
