# Rules.md — 项目记忆与协作规则

## 记忆结构

| 文件 | 用途 | 启动时是否读取 |
| :--- | :--- | :--- |
| `SessionBrief.md` | 当前目标、风险、下一步、模块索引；保持 800~1500 中文字 | 是 |
| `Plan.md` | 仅当前 1~3 个活跃事项 | 是 |
| `ProjectMemory.md` | 稳定架构、底层二进制通信协议、全局契约、硬约束；保持精简 | 否，涉及全局设计/协议变更时读 |
| `contexts/*.md` | 模块当前态与入口（Windows端、Linux端、底层协议）；按任务读取 | 否，按需 |
| `*-archive.md` | 历史快照和已完成项 | 仅追溯历史时读取 |

## 会话开始与按需加载

1. 每个新会话或任务开始时，**必须先读取 `SessionBrief.md` 与 `Plan.md`**，快速掌握项目当前工作态与未完事项。
2. 再按任务类型选择上下文：
   - 涉及 Windows 窗体客户端、DPI、WinForms 交互读 `contexts/Windows.md`；
   - 涉及 Linux 终端、ARM/x86 跨平台构建、Python 版读 `contexts/Linux.md`；
   - 涉及通信协议（UDP/TCP/封包/文件流/TUN穿透/网卡绑定）读 `contexts/Protocol.md`。
3. 涉及全局架构、跨端契约或无法由模块上下文判断的问题，才读取 `ProjectMemory.md`。
4. 用户说“读取记忆”时，严格执行第 1~3 步，不得全量灌入无关历史文件。

## 上下文压缩与记忆保存

### 触发条件（满足其一即执行记忆整理）：
1. 用户说“保存记忆”或“压缩上下文”。
2. 一段独立功能或 Bug 修复收口闭环（例如当前阶段 Windows 与 Linux 通信及 TUN 穿透已彻底验证完成）。
3. 本轮对话显著变长，即将开启新的会话前。

### 保存/压缩步骤（刷新，而非盲目追加）：
1. 更新 `SessionBrief.md`：提炼当前目标、已关闭/未关闭风险、关键约束、下一步计划，字数保持在 800~1500 中文字。
2. 更新 `Plan.md`：仅保留当前仍在进行的 1~3 项计划，已完成的归档至 `Plan-archive.md`。
3. 更新受影响的 `contexts/*.md`，保持模块现状准确。
4. 仅当稳定、跨平台的底层契约变化时才更新 `ProjectMemory.md`。
5. 提交并 Push 至远程 Git 仓库。新会话直接从 `SessionBrief.md` 的「下一步」无缝接手。

## 代码与协作硬约束

1. **独立判断第一优先级**：回答前必须保持独立的技术判断，以指出潜在问题和风险为第一优先级，**严禁默认用户的观点或假定一定正确**。
2. **核定信源与数据**：所有技术决策、参数、代码修改必须有据可循，无法确定或猜测的内容必须做出明确标注并进行实测验证。
3. **提问与实施分离**：用户在提问或探讨阶段只要分析和方案；收到明确实施指令后才修改项目文件。
4. **以最小实现、零冗余依赖为荣**：
   - 绝不随意引入庞大的第三方 NuGet 包或外部依赖。
   - Windows 端必须保持原生极轻量（优先使用 Windows 自带 `csc.exe` 编译，体积控制在几十 KB 级别，免任何运行库安装）。
   - Linux 端确保提供编译好的自包含 ELF 二进制（x86_64 和 ARM64）以及纯标准库的 Python 版本，做到任何发行版与硬件即开即用。
5. **新建类/模块前先归并评估**：
   - 能在现有类、现有协议通道上扩展就绝不新建类。
   - 核心通信服务（`NetworkService`）与模型（`Models`）保持跨平台共用，避免 Windows 与 Linux 双轨维护导致协议分歧。
6. **纯内网安全边界（够用就好）**：
   - 本项目定位于纯局域网环境，威胁模型中无恶意篡改攻击，不进行过度防御设计（如复杂的非对称加解密、多轮验证、繁复的握手状态机），以保持代码极简、传输极速、低内存占用为最高准则。
7. **全中文注释与规范**：所有代码注释、文档一律使用中文；关键网络协议、分块循环、多网卡与 TUN 穿透逻辑必须有详尽注释。
8. **外科式修改**：改动功能时保证现有网络封包魔数与结构向后兼容，改动后必须经过实机/回归编译验证。
9. **UI设计规范与视觉一致性严苛对齐 (GrokBot Design System)**：
   - 界面中所有新增和修改的控件、字体、图标、间距、圆角与色彩，**必须 100% 严格遵守 `LanChat/Docs/GrokBot_UI_Design_System.md` 中定义的度量体系与排版矩阵**。
   - **字体规格严格对标**：主输入与焦点文本必须为 `11.0pt (15px)` `#F2F2F6`（95% 明度）；主要设置/卡片标题为 `10.5pt (14px)` Bold；辅助/提示文字必须为 `9.5pt` `#8E8E93`（57% 明度），严禁使用未经规范的小号缩水字体或低对比暗灰字；
   - **图标引擎与风格高度统一**：所有图标必须通过纯 GDI+ 矢量引擎绘制，线宽保持 `1.6px ~ 2.0px`，端点必须为 `LineCap.Round`，折角为 `LineJoin.Round`；图标尺寸、视觉重心与按钮容器（32px~36px）必须与左侧栏现有成熟图标（搜索圆钮、`+`加号圆钮、向上箭头圆钮）保持完全一致的视觉张力与饱满度，坚决杜绝生硬简陋的细线描边或潦草单线；
   - **杜绝原生白底或异物感控件 (Zero White Scrollbar 契约)**：
     - 暗黑界面中**严禁暴露任何 Windows 原生白底/灰底系统滚动条**（包括 WinForms 原生 `AutoScroll = true`、`VScrollBar`、`HScrollBar` 以及 `ListBox` 原生 `WS_VSCROLL` 滚动条）。
     - 软件中所有存在溢出滚动的视图（包括主界面左侧会话列表 `SessionListBox`、右侧聊天流 `WeChatChatView`、全局设置弹窗 `GrokSettingsDialog` 等）必须**100% 统一使用纯自绘极简暗灰浮动滑块**：
       - 静止状态：4px 宽度，深灰半透明（`#34343C` / `#383840`），极简圆角胶囊形态，悬浮贴靠内容右缘 2px；
       - 悬停/拖拽：微增至 5px，提亮为高对比浅暗灰（`#646470` / `#70707C`）；
       - 完备交互：支持平滑鼠标滚轮加速与鼠标直接按住滑块拖拽定位；无溢出时自动完全隐藏。
     - 严禁使用系统原生直角控件，所有交互按钮、下拉胶囊与卡片必须具备自绘平滑暗黑圆角与悬停反馈（`#202024` / `#28282C`）。

---

10. **单文件行数上限与杜绝上帝类 (Anti-God-Class 强制契约)**：
    - **代码行数警戒线与硬上限（按编辑器行号计，含注释与空行）**：
      - 单个 `.cs` 源码文件达到 **1000 行** 时即触发重构预警：下一次往该文件添加新功能或业务行为之前，必须前置评估并按单一职责原则（SRP）进行模块拆分；
      - **1500 行** 为全工程绝对硬上限：已达到或超过 1500 行的文件（如当前 1914 行的 `GrokSettingsDialog.cs`），**严禁继续盲目追加新业务与卡片容器**，必须先拆分抽离再改动行为。
    - **结构化真解耦，严禁滥用 `partial class` 伪拆分**：
      - 禁止单纯为了规避行数检查，通过 C# `partial class` 关键字将一个高耦合的上帝类机械切成若干个无独立生命周期的碎片文件（这只是切碎了上帝类，并未消灭上帝类）；
      - 必须按**生命周期与业务边界实质拆分**：例如将 `GrokSettingsDialog` 的各个独立子面板拆分为具体的 UserControl/卡片容器（如 `GeneralSettingsPanel.cs`、`AccountSettingsPanel.cs`），主对话框仅承担路由与容器职责；主窗体业务逐步收敛至控制器层；
    - **禁止低质切分与垃圾桶类**：严禁把单个函数截成两半；严禁为了缩减行数新建包含杂乱无章静态方法的垃圾桶类（如 `Utils.cs`、`MiscHelper.cs`）。抽出的类型必须高内聚、职责清晰且自成体系。

## 常用开发构建与发布指令契约 (Tools)

当用户在对话中下达特定快捷指令时，严格按照以下映射调用对应的批处理脚本执行，不得违背：

| 用户指令关键词 | 执行脚本路径 | 行为规范与说明 |
| :--- | :--- | :--- |
| **“编译”** 或 **“纯编译”** | `Tools/Compile.bat` | 仅在项目根目录下调用系统原生 `csc.exe` 极速编译链接 `LanChat.exe` 与 `uninstall.exe`。**不触碰本地安装目录，不打包 MSI，不上传发布**。用于快速语法与链接校验。 |
| **“编译覆盖”** | `Tools/CompileAndLink.bat` | 编译链接 `LanChat.exe`，自动检测并关闭正在运行中的旧程序，将最新程序热替换覆盖至 `D:\soft\LanChat\` 本地安装目录，并同步配套文件。 |
| **“发布”** | `Tools/Publish.bat` | 自动检查并编译 `LanChat.exe`，调用 WiX 5 打包生成 `LanChat.msi`，刷新 Linux deb 安装包，并调用 `publish-release.py` 自动创建/更新 GitHub Release，删除线上同名旧资产并流式上传最新安装包。 |
