# Linux 桌面版可靠性、会话历史与界面改进

**LC-LINUX-001 · 第 2 轮 · 提案方 Codex · 2026-11-18**

审计基线为 `main` 的 `a0e49c1`（`v2.0.16`）和本机同版本 `.deb`。

## 要决定的问题

用户要求逐项衡量 Linux 桌面版与 Windows 的差距，改善界面和日常体验。本轮请审核新增的网络与打包修复、历史格式、Tkinter 实机验证及交付条件。

## 建议决定

### 1. 现有桌面入口先修可靠性

- 群聊重绘先识别系统、文字及文件消息，重绘异常后恢复聊天记录只读状态。首次启动、切回群聊和缩放均保留完整消息。会话按钮明确导航反馈，自动接收控件按已保存的实际配置初始化。
- 发送前检查私聊目标，离线时保留草稿并提示。发出后等待与成功、失败可区分，切换窗口中的会话后仍将结果归到发起处。手动 IP 直连给出参数错误、等待及最终结果。新辅助反馈采用 9.5 pt、`#8E8E93`，错误与危险状态沿用规范色。新增和实质改动的 Python 类与公共方法写中文文档字符串，说明职责、输入输出及异常。
- 按发送者 ID 和连接端点归档收到的文件。文件发送以接收方明确确认落盘为成功。拒收、断开、超时和异常进入明确的终态，保持 64 KiB 流式传输。群聊文件入口无人在线时提示、单人时直发、多人时选择，Linux 控件按 D2 路线处理。
- Python 文字学习保留已知节点经 UDP 公告确认的监听端口和主机名，并防止低置信度的连接信息覆盖已确认路由。首次仅由文字发现时，`38889` 作为临时默认值，等公告后更新。TCP 源端口是连接临时端口。C# 共享核心也有同类覆盖路径，基线矩阵记录触发方向和影响，是否把共享端小修纳入交付由回归结果和审核决定。
- UDP 选址优先采用已经确认属于本地网段的报文源 IPv4。检查公告地址和端口的合法性，参照 Windows 在源为回环或可确认跨网段时才回退到有效的非回环公告 IPv4。网段信息不足时保留源地址和证据状态，实测后再决定归档；覆盖无默认路由和 TUN 环境。TCP 连接地址、发现地址与直连占位的身份归并须可解释。物理网卡枚举与套接字绑定的全面对齐另案处理。
- 协议读取补齐魔数、定长头字段和 EOF 处理，回归已有字符串读取、LANC 帧、端口和 ACK 语义。继续通过队列向 Tk 主线程投递，事件带上来源、发起会话和操作标识。
- 修通 ELF 构建与打包链。按脚本位置定位 `src/linux/LanChat.Linux`，统一输出和打包输入，构建失败要可见且阻止旧 ELF 混入本次候选包。从干净输出目录分别构建两个架构，在候选 amd64 包内比对 ELF 与本轮 x64 输出的 SHA-256。验证 all 包的 Python 路径。公开发布按项目规则另行执行。

### 2. 让会话在节点和应用重启后可找回

- D3 确认后新增历史。采用 Windows 的 `LAN-<IPv4>` 键和 `history_BROADCAST.jsonl`／`history_peer_<键>.jsonl` 文件命名。走 Windows 的消息字段、布尔值、可选 `RemoteAddress` 和本地时间毫秒格式。用双向样例核对 JSON 转义、旧缺字段和时间戳。文件路径按写入端记录，在另一平台仅对实际可读取的路径提供打开操作。 [Windows JSONL 实现](../../src/Services/ChatHistoryService.cs#L283) · [会话键](../../src/Services/SessionManager.cs#L33)
- 安装版沿用用户配置与数据目录，便携版用可写同级数据目录。既有配置保留。覆盖不可写路径、尾部不完整记录、重载去重、确认后清理及重启时未完成发送的显示。文件选择器多选后每个文件单独显示结果，历史中的文件可打开或定位。
- 已确认的局域网 IPv4 归历史，当前节点 ID、地址、端口供路由。离线会话用档案昵称，直连占位转为已发现节点时有足够地址证据才归并。档案记录、同名隔离和同 IP 换实例都要通过。地址被重新分配给另一设备属于当前 IPv4 会话语义的边界。

### 3a. Tk 实机技术验证

用临时原型在 Xorg 和 GNOME Wayland 会话中核对实际 Tk 后端。Tk 8.6 的后端以 `tk windowingsystem` 为准，在 Wayland 桌面同时记录是否通过 XWayland。 [Tk 8.6 手册](https://www.tcl-lang.org/man/tcl8.6.13/TkCmd/tk.htm)

- 对照 Canvas 绘制与 GDI+ 生成 PNG 的图标、圆钮、胶囊、滑块和气泡角。检查 100%、分数缩放和高 DPI 的边缘、透明度、主题效果与资源体积。生成器优先复用 [WeChatIcon.cs](../../src/UI/Renderers/WeChatIcon.cs) 的合规格图标，不同颜色和倍率按需验证。Tk 8.6 有 PNG 格式支持，较老环境的安装和展示降级仍需取证。 [Tk 8.6 Photo 手册](https://www.tcl-lang.org/man/tcl8.6/TkCmd/photo.htm)
- 比较 Canvas 消息流和嵌入圆角资源的 Text，两种方案各放 2000 条文字、系统和文件消息，记录切换、滚动和缩放重绘耗时、滚动锚点及文本选择复制。用 fcitx5 和 ibus 验证候选窗、预编辑、Enter 提交／发送及 Ctrl+Enter 换行。验证窗口内叠加层与系统文件选择器。

### 3b. 正式改造主窗和设置

- 左侧一栏集中搜索、连接节点、在线／离线会话、未读和个人入口。右侧集中标题、圆角聊天气泡、文件卡片和输入胶囊。按 [GrokBot 设计规范](../../Docs/GrokBot_UI_Design_System.md) 使用 `#0E0E0E` 侧栏、`#121212` 聊天底色和 `#202024` 输入底色。输入胶囊 64 px、圆角 32 px，附件钮 36 px、发送钮 44 px，正文按 11 pt 使用高对比文字。按缩放后的逻辑尺寸检查。
- 按 D1、D2 和步骤 3a 的实测选择绘制架构。沿用 [项目规则](../../.claude/Rules.md) 的颜色、线宽和暗色浮动滑块，静止 4 px、悬停或拖动 5 px、无溢出隐藏。保留输入焦点、中文输入法、粘贴和换行，验证会话切换、复制、滚动位置和键盘操作，再收拢重复菜单入口。
- 分类设置集中提供自定义接收目录、自动接收和历史管理入口。主题、强调色与独立字体按布局和缩放验证结果接入。选定的图标与圆角资源应随单文件交付，生成可复现，避免引入 Linux 运行期绘图库依赖。

## 明确不做

本话题的交付范围为内网 Linux 桌面主流程与视觉对齐。跨网通信、批量群发、托盘、原生文件拖拽、表情选择和完整多网卡对齐均是后续可独立决定的话题。Windows 作为互通与视觉验收基线，现有 LANC 协议、Windows 原生轻量构建及三种 Linux 分发入口属于首批兼容约束。
