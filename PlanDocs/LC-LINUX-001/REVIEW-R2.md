## 不成立或说重了

**「C# 是否修改留到回归之后再决定」不能成立。** 提案把非默认端口列为步骤 1 的通过条件，同时又把共享核心的修改留到回归结果出来再定。Windows 收到文字时同样把对方端口写成 `38889`。只改 Python 时，Linux 回复 Windows 的方向可以修好；Windows 回复一台不在 `38889` 上的 Linux 时，仍然会发错端口。这条用例在不改 C# 的情况下必然失败，回归给不出「再决定」所需要的通过结果。

本轮直接决定：**步骤 1 纳入同一处 C# 小修。** 文字学习路径上，节点已经存在时保留它的 `TcpPort` 和 `HostName`，昵称和连接上的 IPv4 可以更新；节点还不存在时，`38889` 和 `LAN-Host` 只作临时值。不改帧格式，用 `Tools/Compile.bat` 验证。Python 使用同一规则。

## 遗漏

下面三条提案没有写死。本轮在「顺序」里补上，不再要求第 3 轮提案。

1. **`Publish.bat` 第 113–114 行把 deb 打包的输出丢掉，失败也打印成功。** 只改正 `build-all.bat` 的目录和 `build-linux.bat` 的输出位置，发布入口仍会把旧 ELF 包成「成功」。步骤 1 要让这个入口传递打包脚本的退出码，失败时不得打印成功，也不得把旧 ELF 放进本次候选包。公开发布仍按项目规则另走「发布」指令。
2. **Windows 的 `UnescapeJson` 只还原 `\\`、`\"`、`\n`、`\r`、`\t`，不认识 `\uXXXX`。** Python `json.dumps` 的默认行为会把中文写成 `\uXXXX`，这样的文件被 Windows 读回后中文会坏。步骤 2 的写入要与 `EscapeJson` 的转义集合一致。双向样例必须包含中文、引号、反斜杠和缺字段的旧行。
3. **「可确认跨网段」需要本机地址和掩码。** `IsInAnyLocalSubnet` 会跳过虚拟网卡后再做掩码比较。步骤 1 用标准库读取地址和掩码，并跳过虚拟网卡；读不到掩码时保留报文源地址，不把它归档成已确认地址。这不等于恢复物理网卡绑定，绑定仍另案处理。
