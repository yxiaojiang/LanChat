# LanChat 方案审核交接

本目录用于审核 LanChat 的范围、技术路线、实施顺序及验收口径。提案方和审核方轮流交接，由用户决定是否采纳。业务代码和差异审核走 [CRDocs](../CRDocs/STATUS.md)。

## 阅读入口和文件归属

先按 [项目规则](../.claude/Rules.md) 加载当前计划和相关模块上下文，再以 [STATUS.md](STATUS.md) 确认话题、轮次、状态和下一位负责人。

| 文件 | 谁写 | 用途 |
| --- | --- | --- |
| [README.md](README.md) | 用户或经用户授权的一方 | 审核流程 |
| [STATUS.md](STATUS.md) | 当前交棒方 | 话题、轮次、状态和下一位负责人 |
| [PROPOSAL.md](PROPOSAL.md) | 提案方 | 本轮完整方案与逐条回应 |
| [REVIEW.md](REVIEW.md) | 审核方 | 本轮独立审核及证据 |
| [DECISIONS.md](DECISIONS.md) | 用户指定的收口方 | 已明确采纳的决定 |

新话题使用 `LC-<模块>-<三位序号>`，例如 `LC-LINUX-001`。每份提案、审核和决定标明话题编号，提案和审核另标轮次。已有历史决定保留原编号。评审中的工期、阈值和支持范围为提案值。

## 提案方

1. 阅读 README、STATUS、REVIEW，以及当前话题涉及的已采纳决定和未决假设。新话题从第 1 轮开始。收到实质修改请求后，保存对应轮次的提案和审核，轮次加一，然后将状态设为 `PROPOSING`。
2. 将本轮完整方案写入 PROPOSAL，使用下列七个二级标题。第一轮最后一节写「无」。后续轮次按意见编号逐条标注「采纳」「部分采纳」或「不采纳」，给出依据与提案改动位置。
3. 将 STATUS 设为 `READY_FOR_REVIEW`，填写审核方和下一步。提案方维护提案和交接状态。

```text
## 要决定的问题
## 建议决定
## 证据
## 未核实
## 建议顺序
## 明确不做
## 对上一轮审核的处理
```

## 审核方

1. 阅读 README、STATUS 和 PROPOSAL，核对话题和轮次，并查看相关已采纳决定。独立检查提案引用的源码、脚本、安装产物和测试。写明路径、搜查范围、测试环境及结果。把用户要求、源码事实、实测结果和方案假设各自写清楚。仅有回环证据时，把真实局域网和 Linux 桌面验证留为待核实。
2. 按实际入口核对功能。Linux 的 `.deb` 桌面入口、Python 单文件的 GUI／CLI，以及复用 C# 网络核心的自包含 ELF CLI 分别取证。涉及网络时检查 LANC 帧、端口、双向互通、发现和文件最后确认。涉及历史时检查新旧记录、节点重启、同名及离线会话。涉及 UI 时对照 [GrokBot 设计规范](../Docs/GrokBot_UI_Design_System.md) 和项目规则，核对安装依赖、缩放、中文输入、键盘和浮动滚动条。按话题选取适用项。
3. 在 REVIEW 中给实质意见编号，说明影响哪一步以及最小修正。同意时也写明核对了什么。给出「不改」或调整后的完整顺序。业务代码、提案和已采纳决定由对应角色维护。
4. 同步更新 STATUS，给出结论与下一位负责人。审核稿使用下列七个二级标题。

```text
## 本轮核对了什么
## 属实
## 不成立或说重了
## 遗漏
## 顺序
## 未核实
## 结论
```

## 状态与采纳

| 状态 | 含义与下一位 |
| --- | --- |
| `IDLE` | 等待用户提出新话题 |
| `PROPOSING` | 提案方准备本轮方案 |
| `READY_FOR_REVIEW` | 独立审核方核对并交棒 |
| `CHANGES_REQUESTED` | 存在会改变下一步的事实错误、遗漏或顺序问题，提案方修订 |
| `CONVERGED` | 可以按提案启动下一步，由用户决定是否采纳 |
| `BLOCKED` | 缺决定性证据或用户决定，由 STATUS 指定负责人补齐，并写明恢复条件 |
| `ADOPTED` | 用户已明确采纳，由指定方完成记录和归档 |

一个话题最多三轮。第 3 轮审核结论为 `CONVERGED` 或 `BLOCKED`，可继续保留的风险写入未决假设。

采纳后，指定方将日期、话题编号、决定、顺序、未决假设和定稿路径写入 DECISIONS。把各轮稿件、最终提案、对应审核和收口状态保存在 `PlanDocs/<话题编号>/`，核对链接后将顶层入口恢复为 `IDLE`。当前执行计划和项目记忆按 [项目规则](../.claude/Rules.md) 更新。业务实施、覆盖安装和发布按用户指令及项目规则执行。

## 用户交接用语

- 提案：「读取 PlanDocs，把这件事写成提案并交接。」
- 审核：「读取 PlanDocs，独立审核当前话题和轮次，写入 REVIEW.md 并更新 STATUS.md。」
- 修订：「读取 PlanDocs，按当前轮 REVIEW.md 逐条修订提案并交接。」
- 采纳：「我采纳这份方案，按 PlanDocs 规则记录决定并更新计划。」
