# LanChat V4.0 · Windows/Linux 功能统一计划

> 分支：`codex/v4.0-cross-platform-unification`
> 基线：`V3.0`，程序输出版本 `2.0.26`
> 目标：在不破坏 LANC/JSONL 兼容性的前提下，使 Windows 与 Linux 的用户可见功能、设置行为和桌面生命周期尽可能统一。
> **实施口径更新（2026-11-26）**：本路线已通过 [LC-LINUX-003](LC-LINUX-003/FINAL.md) 方案审核与采纳（**D1=A、D2=A、D3=A** + 4 条实施护栏），已明确不做“新建节点（14 形态）”空壳窗及 C 类 4 项假开关（三语切换、内置网页预览、64KB `Flush(true)` 刷盘、复杂通道切换）。具体代码修改顺序与验收标准请严格以 [LC-LINUX-003 定稿](LC-LINUX-003/FINAL.md) 和 [执行计划](../.claude/Plan.md) 为准。

## 当前基线

V3.0 已具备稳定使用所需的文字聊天、群聊、表情、文件传输、剪贴板附件、历史记录、主题/字体设置和双架构 Linux 包。Linux 主窗、聊天、文件进度、表情资源、八页设置及共享 C# 通信服务已经存在；以下项目是 V4.0 的重点差异，不应重复实现已有功能。

## 优先目标

1. **桌面生命周期统一**：Linux 托盘恢复、真正退出、关闭窗口策略、未读提醒和系统通知；按 Xorg、原生 Wayland、XWayland 分别定义可验收的等效操作。
2. **节点管理统一**：补齐 Linux Electron 的连接节点、新建节点、搜索、手动 IPv4 直连和设备信息入口，复用共享发现与握手服务。
3. **设置真实接线**：将语言、链接打开方式、后台驻留、协议通道、64KB 校验、自动加载历史、TUN/TAP 过滤、多网卡探测等展示项接入真实配置或明确标记为平台不适用。
4. **更新与维护统一**：Linux 检查更新、架构资产选择、安装/升级/回退说明，以及反馈和诊断入口。
5. **跨环境验收**：完成 Linux ELF、Xorg/Wayland/XWayland、fcitx5/ibus、100%/125%/150% DPI、amd64/ARM64、真实 Windows LAN 和旧版本互通矩阵。

## 实施顺序

- 阶段 0：冻结 Windows V3.0 操作基线，建立 Windows/Linux 差异矩阵。
- 阶段 1：实现 Linux 桌面生命周期与通知，先完成恢复路径再改变关闭语义。
- 阶段 2：实现 Linux Electron 节点管理 GUI，所有网络动作经受限 preload IPC 调用共享 C# 服务。
- 阶段 3：逐项接通设置，区分可跨平台共享的配置与 Linux 桌面等效配置。
- 阶段 4：接入更新/维护入口，补齐双架构资产和升级回退演练。
- 阶段 5：执行 Linux 实机、双架构和真实局域网验收，更新 `CRDocs/DEFERRED.md` 与发布文档。

## 硬约束

- 不重写网络协议，不复制 `NetworkService`，保持 LANC 封包和 JSONL 历史兼容。
- Windows 端行为不得回归；Linux GUI 与 CLI 必须共用数据路径和通信核心。
- 先补自动化回归，再做桌面实机验收；静态或 Windows 宿主机测试不得替代 Linux 实机证据。
- Linux 手写 JavaScript、CSS、C# 文件达到 1000 行时必须先评估拆分，1500 行为硬上限。
