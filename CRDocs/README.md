# 执行者–审核者代码协作机制

`CRDocs` 是执行者与独立审核者的长期交接面。开始工作前必须读取本文件、`RULES.md`、`STATUS.md`、`REVIEW.md`、`IMPLEMENTATION.md` 和 `DEFERRED.md`。历史审核不在活动文件中无限追加，统一通过 [`archive/INDEX.md`](archive/INDEX.md) 查找。

## 活动区与归档区

| 区域 | 规则 |
| --- | --- |
| `STATUS.md` | 只记录当前任务的状态、范围、结论、边界和下一步；附最近 3 轮状态索引。 |
| `REVIEW.md` | 只保留当前任务最近 3 轮审核/整改交接，按最新在前排列。 |
| `IMPLEMENTATION.md` | 只保留当前任务最近 3 轮执行记录、验证证据和边界。 |
| `DEFERRED.md` | 只保留仍然有效的延期项；已关闭或只属于历史任务的条目随该任务归档。 |
| `archive/<日期>_<审核内容概要>/` | 存放超过 3 轮的完整历史；目录必须有 `INDEX.md`，原始 Markdown 文件与索引一起保存。 |

“一轮”是一次独立审核及其对应的执行者整改/交接记录；同一轮的多个文件算一轮，不按文件数重复计算。当前任务切换时，旧任务的全部活动记录先归档，再建立新任务的活动记录。

## 归档流程（硬规则）

1. 在活动文件新增第 4 轮之前，先把最旧的一轮完整内容移入新建归档目录；不得直接删除或覆盖历史。
2. 归档目录命名为 `YYYY-MM-DD_<任务或阶段>_<审核内容概要>`，概要应能表达主题和审核结论，例如 `2026-11-26_历史审核_阶段0-3与UI输入传输收口`。
3. 归档目录内必须有 `INDEX.md`，列出任务编号、轮次、结论、日期、原始文件和检索关键词；根目录 [`archive/INDEX.md`](archive/INDEX.md) 必须同步增加入口。
4. 活动区只保留可直接指导下一步的内容。历史问题、原始命令输出和完整逐项证据以归档文件为准；活动文件通过相对链接指向归档，不复制整段历史。
5. 归档后检查活动区行数、链接、状态和 `git diff --check`。不得因压缩历史而改变审核结论、问题 ID、延期条件或验证边界。

## 执行者（Executor）

1. 读取 `STATUS.md`、`REVIEW.md`、`DEFERRED.md` 和相关归档索引。
2. 只处理当前阶段仍为 `OPEN` 且属于当前任务的问题，不擅自扩大范围。
3. 修改代码并执行适当的回归、语法、编译、静态测量和行数门禁。
4. 把本轮改动、验证、未验证项和边界写入 `IMPLEMENTATION.md`；若会超过 3 轮，先归档最旧轮次。
5. 把 `STATUS.md` 更新为 `WAITING_FOR_GROK`。执行者不得自行写入 `APPROVED`。
6. 不修改审核者已经写出的结论；异议写入本轮实施记录。

## 审核者（Reviewer）

1. 读取 `STATUS.md`、`IMPLEMENTATION.md`、`DEFERRED.md`，必要时按索引追溯归档。
2. 必须检查实际代码、协议/IPC 边界、diff、调用链和必要的独立命令，不以执行者说明替代证据。
3. 默认只审核，不修改业务代码；用户明确授权时才修复代码。
4. 把结论、P0/P1/P2 分级问题、复核证据和边界写入 `REVIEW.md` 顶部；新增第 4 轮前先归档最旧轮次。
5. 已修复问题标记 `RESOLVED`，不要在后续轮次重复提出；未来阶段或环境验证项转入 `DEFERRED.md`。
6. 仍有 P0/P1 时将 `STATUS.md` 置为 `REJECTED`；当前范围闭环才置为 `APPROVED`。

## 状态和问题词汇

- 任务状态：`WAITING_FOR_GROK`、`REJECTED`、`APPROVED`、`BLOCKED`、`SUPERSEDED`。
- 问题结论：`OPEN`、`RESOLVED`、`DEFERRED`、`WONT_FIX`。
- `APPROVED` 只代表 `STATUS.md` 明确写出的范围和证据通过，不代表整个项目、Linux 实机或物理 LAN 已验收。

## 不可突破的协作约束

- 稳定问题 ID 不得跨轮改名；基线、协议和代码不一致时先说明需求来源，不为迁就实现而降级协议。
- 遵循最小实现、现有结构和源码行数门禁；P2 与跨平台环境项不阻断当前切片时登记延期。
- 所有宿主机 Mock、DOM/IPC 桩、纯逻辑和交叉编译证据必须明确标注，不能写成 Linux/ELF 实机通过。

## 用户最简提示词

执行者：`读取 CRDocs，按 REVIEW.md 修改；完成后按规则交接。`

审核者：`读取 CRDocs，独立审核当前任务；回写 REVIEW.md 和 STATUS.md；超过 3 轮时先归档最旧轮次，并交出下一份提示词。`
