# CRDocs 回写与交接规则

本目录是代码审核与整改的交接面。审核者和执行者做完本轮工作后，必须先把结果写入下面两个文件，再在回复里给出下一位可直接粘贴的提示词。只在对话里口头结论、不改这两个文件，视为本轮未完成。

| 文件 | 谁写 | 写什么 |
| :--- | :--- | :--- |
| `CRDocs/STATUS.md` | 审核者、执行者 | 当前任务编号、主题、状态、日期、报告路径、一句话结论、下一位要做什么 |
| `CRDocs/REVIEW.md` | 审核者、执行者 | 本轮完整意见或执行记录。审核写结论、分级问题和维度核对；执行写改了什么、怎么验证、哪些仍未验证 |

## 状态词

- `WAITING_FOR_GROK`：执行者已送审，等待独立审核。执行者不得把自己的结果写成 `APPROVED`。
- `REJECTED`：审核打回。执行者按 `REVIEW.md` 的 P0、P1 整改后再送审。
- `APPROVED`：只有独立审核者在核对代码和证据之后可以写入。执行者禁止写入这个状态。

## 审核者做完

1. 用审核结论覆盖 `CRDocs/REVIEW.md`（保留任务编号、日期、依据和验证边界）。
2. 把 `CRDocs/STATUS.md` 改成 `APPROVED` 或 `REJECTED`，写明下一位动作。
3. 回复用户时给出交接提示词：打回则交给执行者，放行则交给下一项任务的执行者。

## 执行者做完

1. 在 `CRDocs/REVIEW.md` 写下本轮执行记录：改动、验证命令和结果、未跑的环境。未在 Linux 或 ELF 上跑过的用例必须写成未验证。
2. 把 `CRDocs/STATUS.md` 改成 `WAITING_FOR_GROK`。不得写成 `APPROVED`。
3. 回复用户时给出交给审核者的提示词。提示词要写明任务编号、必读的 `CRDocs/RULES.md`、`STATUS.md`、`REVIEW.md`，以及审核结束后必须回写这两个文件再交出下一份提示词。
